# 0002 — Контракт админ-панели

- **Статус:** принято 2026-11-05
- **Область:** `admin/`, `internal/database/*_admin.go`, `admin/src/`
- **Заменяет:** ничего; дополняет `admin/AGENTS.md` (тот описывает механику, этот — правила)

## Контекст

Панель — второстепенная часть бота: один администратор, локальный доступ,
реальная SQLite. Сейчас в ней один экран (планы). Дальше появятся продукты,
ноды, инвайты, подписки, заказы, рассылки, журнал аудита — 7 экранов, и без
общего контракта каждый будет решать одни и те же вопросы заново: что можно
менять, как выглядит список, какие коды ошибок, откуда берётся аудит.

Документ фиксирует эти решения один раз. Всё, что здесь написано, —
обязательно; отклонения оформляются новым ADR.

## Решения

### 1. Доступ (P1–P6)

| # | Решение |
|---|---|
| P1 | Один общий `ADMIN_TOKEN`, сравнение через `crypto/subtle`, заголовок `Authorization: Bearer`. Ролей и логинов нет; второй админ — отдельная таблица `admin_tokens` (миграция), не роли в коде |
| P2 | Токен в `sessionStorage` вкладки. Cookie не используются → CSRF невозможен; CORS-заголовков нет, панель живёт на том же origin |
| P3 | Rate limit: 10 неудачных авторизаций в минуту на IP, in-memory; успешный вход счётчик сбрасывает |
| P4 | Тело запроса ≤ 64 KiB (`http.MaxBytesReader`), `Content-Type: application/json`, неизвестные поля → `400` (`DisallowUnknownFields`) |
| P5 | Слушатель по умолчанию loopback. На не-loopback адресе — `WARN` при старте. TLS панель не умеет: снаружи только SSH-туннель или реверс-прокси |
| P6 | `Cache-Control: no-store` на `/admin/api/*`; ассеты `dist` хешированные и неизменяемые |

### 2. Матрица прав

| Сущность | Панель | Через что | Guard |
|---|---|---|---|
| `plans` | CRUD | `plans_admin.go` | `free`/`trial` переименовать и удалить нельзя; `trial` нельзя выключить; план с продуктами/подписками — `409 in_use` |
| `products` | CRUD | `products_admin.go` | удаление при активных подписках — `409 in_use`; `plan_id` обязан существовать |
| `nodes` | CRUD, `api_token` write-only | `nodes_admin.go` | удаление при привязках `plan_nodes` или `subscription_nodes` — `409 in_use`; секрет не читается никогда |
| `plan_nodes` | CRUD (привязки) | `plan_nodes_admin.go` | пара (plan, node) уникальна — `409`; добавлять неактивную ноду можно, но UI помечает |
| `invites` | CRUD (создать/отозвать) | `invites_admin.go` | использованный инвайт не удаляется, только помечается |
| `subscriptions` | **чтение** + 3 операции | `SubscriptionService` | никогда прямая запись в таблицу |
| `orders` | **чтение** | SQL-репозиторий | — |
| `subscription_nodes` | **чтение** | SQL-репозиторий | — |
| `broadcasts` | CRUD + запуск через очередь БД | `broadcast_admin.go` | `running` нельзя править или удалять — `409 in_use` |
| `audit_log` | **чтение** | `audit_log_repo.go` | append-only, панель только фильтрует |

Общее правило: **панель меняет конфигурацию, но не состояния.** Любое поле,
которое двигает state machine (`subscriptions.status`, `orders.status`,
`subscription_nodes.pending_*`, `broadcasts.status`), меняется только сервисом
бота. Панель вызывает сервис и получает результат.

### 3. Формат API (P7–P14)

| # | Решение |
|---|---|
| P7 | Список всегда `{"items":[…],"total":N}`. Пагинация `?limit=` (по умолчанию 50, максимум 200) и `?offset=` — обязательна для растущих таблиц: `subscriptions`, `orders`, `audit_log`, получатели рассылок. Для `plans`, `products`, `nodes`, `plan_nodes`, `invites` отдаётся полный список (клиентская фильтрация) |
| P8 | `?q=` — поиск, `?sort=<field>&order=asc\|desc` — сортировка; белый список полей объявлен в хендлере, неизвестное значение → `400 bad_request` |
| P9 | Ошибка: `{"code":"…","message":"…","details":{…}}`. Коды: `bad_request`, `validation` (`400` + `details{field: причина}`), `unauthorized` (`401`), `not_found` (`404`), `name_taken` / `protected` / `in_use` / `stale` (`409`), `internal` (`500`) |
| P10 | `PUT` — полная замена редактируемых полей. Отсутствующий необязательный ключ = значение по умолчанию, кроме секретов: пустая строка означает «не менять» |
| P11 | Мутация возвращает изменённый объект (`200` + JSON), а не `{"ok":true}` — UI обновляет строку без второго запроса |
| P12 | Ответ `204` не используется нигде: Chromium пишет `net::ERR_ABORTED` на `204` после `PUT`/`DELETE`, и это выглядит как падение |
| P13 | Повторный `DELETE` по отсутствующей строке → `404 not_found` |
| P14 | Оптимистической блокировки нет: админ один, конфликт = last-write-wins. `updated_at` возвращается в каждом объекте, UI показывает свежесть |

### 4. Единицы и время (P15)

- трафик — **байты**, `int64`, `0` = без лимита;
- деньги — **центы**, `int`;
- длительность — **дни**, `int`;
- время — RFC3339 **UTC** в API, локаль браузера в UI.

Конвертация (`formatBytes`, `formatMoney`, `formatDate`) живёт только в
`admin/src/lib/format.js`. В API не бывает строк «20 ГБ» и «399 ₽».

### 5. Секреты (P16)

`nodes.api_token` и любые будущие ключи панелей/платёжек:

- никогда не появляются в JSON-ответах, логах и сообщениях об ошибках;
- в ответе только `has_api_token: bool`;
- на запись — поле «задать новое значение»; пустая строка = не менять.

### 6. Границы мутаций (P17–P20)

| # | Решение |
|---|---|
| P17 | Прямая запись полей состояния запрещена (см. §2). Нарушение — повод отклонить код-ревью |
| P18 | Рассылки: панель делает `INSERT` со `status="scheduled"` и `planned_at`, а подхватывает воркер (`GetRunnableBroadcasts`, тик 15 с, батч 100). Сообщения в Telegram панель не отправляет. Отмена — `CancelBroadcast`. Правка запланированной рассылки требует нового репозиторного метода `UpdateBroadcastDraft` (`UpdateBroadcast` пишет только счётчики и статус) |
| P19 | Подписки — ровно три операции. «Продлить/сменить план» — существующий `AdminSetPlan`. «Отозвать без удаления» — новый экспортируемый `RevokeSubscription` (`markRevokedSub` + `deprovisionSub`). «Удалить» — `DeleteByID` (revoke + deprovision + удаление строки). Отдельного «сбросить трафик» нет: нужен `SyncService.ResetSubscriptionTraffic`, вызывающий `client.ResetTraffic` по всем активным нодам (best-effort, как в `ApplyPlanToSubscription`) |
| P20 | Аудит: каждая панельная мутация пишет событие `actor_type=admin`, `actor_id=0` (**0 = панель**, Telegram ID всегда > 0) через `service.WithAuditAdmin(ctx, 0)`. Новые события — конструкторы в `internal/database/audit_log.go`: `AuditPlanCreated/Updated/Deleted`, `AuditProduct*`, `AuditNode*`, `AuditPlanNode*`, `AuditInvite*`, `AuditBroadcast*`. Best-effort, кроме платёжных транзакций |

### 7. Удаление (P21)

Только физическое удаление. Удалять можно лишь строку без зависимостей; иначе
`409 in_use` с перечнем зависимостей в `details` (`products: 4`,
`subscriptions: 64`). Soft archive отклонён: он требует миграции и фильтра во
всех запросах бота — цена ошибки «архивный план всё ещё выдаётся» выше цены
потерянной строки.

### 8. Структура кода (P22–P24)

| # | Решение |
|---|---|
| P22 | Один экран = четыре файла: `internal/database/<entity>_admin.go` (SQL + sentinel-ошибки), `admin/<entity>.go` (узкий интерфейс + хендлеры), `admin/src/views/<Entity>.svelte`, одна строка в карте маршрутов `src/App.svelte` |
| P23 | Sentinel-ошибки: `ErrXInvalid`, `ErrXNameTaken`, `ErrXProtected`, `ErrXInUse`; маппинг в JSON — один `writeStoreError` на пакет. Голых `fmt.Errorf` для отказов быть не должно |
| P24 | Модели БД в JSON не отдаются: для каждого экрана отдельный DTO в `admin/`. Случайно добавленное поле не утекает в API |

### 9. UI (P25–P29)

| # | Решение |
|---|---|
| P25 | Общие компоненты в `src/lib/`: `Table`, `Modal` (`<dialog>`), `Field`, `Badge`, `Pagination`, `EmptyState`, `Notice`. Никаких UI-китов и CSS-фреймворков |
| P26 | Модалка — для сущностей ≤ 12 полей. Отдельная страница (`#/subscriptions/42`) — там, где есть история, связанные строки и несколько операций |
| P27 | Каждый список умеет четыре состояния: загрузка, пусто, ошибка, «только чтение» (бейдж). Деструктив — подтверждение с перечнем зависимостей из `details` |
| P28 | Никакого polling и WebSocket: кнопка «Обновить» + перезагрузка списка после мутации. `401` → очистка токена и экран входа |
| P29 | Тексты интерфейса — русские, идентификаторы и комментарии в коде — английские |

### 10. Тесты (P30–P31)

| # | Решение |
|---|---|
| P30 | На каждый экран: таблица sentinel-кейсов на реальной SQLite (как `plans_admin_test.go`) + HTTP-тесты на `200/400/401/404/409`. UI — ручной чек-лист в `admin/AGENTS.md`, без браузерных тестов в CI |
| P31 | Фейки БД не пишутся; `TestMain` инициализирует логгер один раз (иначе гонка на `logger.Init` в параллельных подтестах) |

### 11. Порядок реализации

1. **Продукты** — планы уже ссылаются на них, удаление `premium` блокируется.
2. **Ноды + привязки к планам** — `api_token` write-only, health-бейдж.
3. **Инвайты** — создание/отзыв, использованные только читаются.
4. **Подписки** — read-only список/карточка + три операции (нужен `RevokeSubscription`).
5. **Заказы** — read-only, фильтр по статусу и дате.
6. **Рассылки** — черновик, расписание, отмена, прогресс (нужны `UpdateBroadcastDraft`, `DeleteBroadcast`, `CountBroadcastAudience`).
7. **Журнал аудита** — read-only, фильтры по сущности/событию.

## Отклонённые альтернативы

| Альтернатива | Почему нет |
|---|---|
| Полный CRUD подписок | Обходит провижининг, депровижининг, каскад заказов и аудит: панель стала бы второй копией `SubscriptionService` |
| Физическое удаление планировалось как soft archive | Скрытая строка продолжает выдаваться ботом; нужен фильтр во всех запросах |
| Optimistic locking (`If-Match`) | Один админ; версии добавляют 409-на-ровном-месте без реальной пользы |
| `204 No Content` | `net::ERR_ABORTED` в консоли Chromium |
| `svelte-spa-router`, UI-кит, Tailwind | Лишние зависимости и обновления; хеш-роутинг — 10 строк |
| Отдельный фронтенд-сервис / SSR | Противоречит требованию «панель не занимает много места» |
| Роли и несколько админов | Не нужны сейчас; точка расширения — `admin_tokens` |

## Последствия

**Требуется дописать в сервисном слое:**

- `SubscriptionService.RevokeSubscription` (отзыв без удаления);
- `SyncService.ResetSubscriptionTraffic` (сброс счётчика по активным нодам);
- репозиторий рассылок: `UpdateBroadcastDraft`, `DeleteBroadcast`, `CountBroadcastAudience`;
- конструкторы аудита для планов, продуктов, нод, привязок, инвайтов, рассылок.

**Принятые ограничения:** один администратор; нет TLS; нет пагинации для
малых таблиц; аудит панельных мутаций пишется best-effort (кроме транзакций
оплаты, до которых панель не достаёт).

**Проверка соблюдения контракта:** `go test ./admin/ ./internal/database/`,
`golangci-lint run ./...`, ручной чек-лист экрана.
