# 1–7 июня 2026

**rs8kvn_bot выходит на новый уровень: подписка больше не зависит от одной панели**

Первая неделя июня стала для проекта архитектурной точкой перехода. За 40 рабочих коммитов мы заложили основу мульти-источников и превратили выдачу подписок в полноценный subscription server.

**Что изменилось для пользователей:**

• **Несколько панелей 3x-ui вместо одной.** Подписка теперь может собираться из нескольких источников. Если один узел временно недоступен, система получает возможность использовать остальные — без привязки всей выдачи к одной точке отказа.

• **Новая модель подписки: планы и источники.** Лимиты, типы доступа и источники вынесены в отдельные сущности. Это делает конфигурацию гибче: проще добавлять тарифы, подключать новые панели и управлять правилами доступа без переписывания пользовательского потока.

• **Подписочный сервер агрегирует конфигурации.** Клиент получает единый профиль, собранный из доступных источников. Для пользователя это один URL подписки, даже если за ним работает несколько панелей.

• **Отслеживание устройств и IP.** Данные о подключениях стали частью подписочного контура. Это фундамент для более прозрачного контроля доступа и диагностики проблем.

• **Trial-flow стал надёжнее.** Привязка пробной подписки учитывает несколько источников и корректнее сохраняет реферальные данные. Гонки при одновременных действиях больше не должны превращаться в двойные или потерянные привязки.

**Самое важное:** мы перестали масштабировать продукт «вширь» вокруг одной панели. Теперь в основе — модель, которая рассчитана на несколько узлов, разные планы и дальнейшее развитие инфраструктуры.

Попробуйте обновлённый сценарий подписки и поделитесь впечатлениями реакцией. Следующий шаг — сделать эту архитектуру ещё удобнее в эксплуатации и для разработчиков.
