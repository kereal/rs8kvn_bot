- Панель остаётся только читающей по состояниям бота. Refund, подтверждение оплаты и прямое редактирование подписок не делать.
- Все мутации через существующие сервисы. Прямые `UPDATE subscription_nodes` запрещены.
- Новых npm-зависимостей и UI-библиотек не добавлять.
- В один PR объединять только независимые небольшие правки. Задачи 1–3, 7–8 делать отдельными PR.
- После каждой задачи: `make check`, `golangci-lint run ./...`, `go test -race ./... -count=1`, `cd admin && npm run build`, `git diff --check`.

## 1. Заказы с ручной сверкой

### Цель

Показать платежи, у которых результат создания платежа неизвестен: деньги могли списаться, но провайдер не дал однозначного ответа.

### Что уже есть

- `orders.payment_creation_uncertain`.
- Событие аудита `payment_creation_uncertain`.
- Поле уже возвращается в DTO заказа.
- Нет ни фильтра, ни UI.

### Что сделать

- В `internal/database/orders_admin.go` добавить фильтр `OrderAdminFilter.Uncertain *bool`.
- В `admin/orders.go` добавить `GET /admin/api/orders?uncertain=true`.
- В `admin/src/views/Orders.svelte` добавить фильтр и бейдж «Требует сверки».
- В `admin/src/views/OrdersDetail.svelte` добавить карточку с `provider_payment_id`, валютой, суммой и `payment_url`.
- В `internal/database/overview.go` и `admin/overview.go` добавить счётчик таких заказов.
- На Overview сделать переход на отфильтрованный список заказов.

### Требования

- Только чтение. Никаких кнопок подтверждения, повторной оплаты и возврата.
- `payment_url` показывать только в детали, не в списке.
- Не считать неопределённый заказ оплаченным.
- Фильтр и `total` должны строиться одним `WHERE`.

### Принимается

- Заказ с `payment_creation_uncertain=true` виден в списке и на Overview.
- Переход с Overview ведёт к отфильтрованному списку.
- Есть HTTP-тесты на `200/400/401`.
- Существующие заказы без признака не попадают в фильтр.

## 2. Gross / refund / net выручка

### Цель

Сделать финансовую семантику честной: различать платёж, возврат и net-выручку.

### Проблема

Сейчас выручка считает только `paid`. После возврата заказ становится `canceled` и исчезает из выручки. Это неудобно для финансового контроля.

### Что сделать

- Добавить долговечные поля заказа, например `refunded_at`, `refund_amount_cents`, `refund_kind`.
- Заполнить их в существующих refund/chargeback-транзакциях.
- Расширить `GET /admin/api/revenue` полями:
  - `gross_revenue_cents`;
  - `refunded_cents`;
  - `net_revenue_cents`;
  - `refund_count`.
- На Overview показатьgross, возвраты и net.
- На странице заказа показать refund/chargeback и факт понижения до free.

### Требования

- Refund остаётся только у бота.
- Нельзя восстанавливать финансовый факт из audit log.
- Валюты не смешивать.
- Chargeback и обычный refund различать.
- Для Stars учитывать split-brain: provider refund уже применён, локальный статус ещё нет.

### Принимается

- Есть миграция.
- Refund/chargeback пишет финансовые факты в заказ.
- API отдаёт gross/refund/net.
- Валюты раздельно.
- Есть тесты на mixed RUB/XTR, refund и chargeback.

  - `retry_count`;

  - `last_error`;
  - `updated_at`.
- Из строки дать ссылку на существующий `POST /admin/api/subscriptions/{id}/sync`.
- Сортировать по возрасту записи.

### Требования

- Только чтение.
- Никаких прямых `UPDATE subscription_nodes`.
- `last_error` ограничить по длине и не раскрывать секреты.
- Не опрашивать ноды автоматически.

### Принимается

- Очередь видна на Overview и в отдельном списке.
- Видно конкретную подписку, ноду, количество попыток и ошибку.

## 7. Активный платёжный режим

### Цель

Показать администратору, какой провайдер и какие валюты сейчас активны.

### Что сделать

- Добавить read-only endpoint `GET /admin/api/payment/config`.
- Ответ, например:
  ```json
  {
    "provider": "telegram_stars",
    "enabled": true,
    "supported_currencies": ["XTR"]
  }
  ```
- На Overview добавить карточку «Платежи».
- На Products предупреждать о валюте, не поддерживаемой активным провайдером.
- Не блокировать создание произвольной валюты пока явно не решено.

### Требования

- Никаких API keys, webhook secret, bot token и Stars credentials.
- Панель не переключает провайдер.
- Endpoint не создаёт второй источник истины по настройкам.

### Принимается

- Endpoint отдаёт только безопасные поля.
- На Overview виден активный провайдер.
- На Products есть предупреждение при несовместимой валюте.

### Что сделать

- Добавить `POST /admin/api/nodes/health/check`.
- Ответ: список результатов по нодам.

- На Overview показать последний результат проверки или предупреждение о недоступных нодах.

### Требования

- Только ручной запуск. Фонового polling нет.
- Ошибка сети — данные `available:false`, а не HTTP `500`.

- Не вызывать unsupported health-клиенты.

### Принимается

- Есть endpoint и UI.
- Ответ не падает на одной недоступной ноде.
- Есть тесты на 200/401 и деградацию.
