## Статус приёмки ТЗ (2026-11-05)

Все критерии раздела «Критерии приёмки» в 01–08 сверены с кодом и отмечены;
у каждого пункта в ТЗ стоит ссылка на файл:строка или имя теста.

| Что проверялось | Как |
|---|---|
| каждый критерий 01–08 | чтение кода, полярная проверка по графу/грепу: реестры, отсутствие write-путей, склейка SQL, гейты блокировок, аудит-акторы |
| поведение экранов | собранная панель (`tools/adminserve -seed`) в headless Chromium: экран по умолчанию, фильтр событий, create/update/delete продукта, консоль и page errors пусты |
| сервер и БД | `go test -race ./...`, `go test ./tests/e2e/`, `golangci-lint run ./...` — зелёные |
| фронтенд | `npm run check` (svelte-check) — 0 ошибок |

Ручными остаются только два пункта, оба помечены в своих ТЗ: сверка
`build.version` с `docker inspect` на собранном образе (08-5) и реальная
сетевая доставка рассылки в Telegram (06-2, в e2e отправка через фейк).

Найденные при сверке расхождения исправлены кодом, а не пометками:
`recipients_total` публикуется снапшотом (06-3), реестр
`/admin/api/audit/events` дополнен 13 событиями и сверяется тестом с
константами `audit_log.go` (07-5). Критерий 07-2 («audit_log.go не изменён
ни на строку») опирался на неверную предпосылку и переформулирован под
инвариант AGENTS.md.

## Шаблон ТЗ

Каждое ТЗ содержит ровно эти разделы, в этом порядке:

1. **Цель и границы** — что делает экран, чего он не делает (вне скоупа).
2. **Данные** — фактическая схема таблиц, ограничения, существующие методы.
3. **Права и guard'ы** — что можно менять, при каких условиях отказ.
4. **API** — таблица `method/path/query/body/response/errors`, DTO поле-в-поле.
5. **Сервер** — новые методы репозитория с сигнатурами и поведением, sentinel-ошибки.
6. **Аудит** — события и их `old_state`/`new_state`.
7. **UI** — колонки, поля формы, состояния, форматирование, тексты.
8. **Тесты** — таблица кейсов с ожидаемым кодом/ошибкой.
9. **Критерии приёмки** — проверяемые утверждения, не «работает».
10. **Файлы** — какие создаёт, какие правит одной строкой, какие запрещено трогать.
11. **Вне скоупа** — что явно не входит, чтобы агент не расширял задачу.

## Правила для агента, взявшего ТЗ

**Владеет этими файлами** (создаёт или переписывает целиком):

- `internal/database/<entity>_admin.go` + `<entity>_admin_test.go`;
- `admin/<entity>.go` (+ кейсы в существующих `_test.go` или новый файл);
- `admin/src/views/<Entity>.svelte`.

**Правит одной строкой** (только свою запись, ничего вокруг):

- карта `routes` в `admin/src/App.svelte`;
- пункт в боковом меню там же;
- `mux.HandleFunc` в `Handler()` в `admin/server.go`.

**Не трогает никогда:**

- `admin/src/lib/*` (общие компоненты и `format.js`). Запросы делает через
  готовые `api.get/post/put/del` из `src/lib/api.js`; именованные обёртки
  (`api.listNodes` и т.п.) добавляются интегратором централизованно, чтобы
  каждый экран не правил общий файл; нужен новый примитив — пишет запрос в
  приёмку ТЗ, а не «поправлю по-быстрому»;
- `admin/dist/*` — собирает интегратор после слияния веток, иначе каждый
  коммит перетирает чужие ассеты;
- `internal/database/audit_log.go` — **кроме** добавления своих конструкторов
  событий (это разрешено и обязательно);
- сервисный слой (`internal/service/*`) — если ТЗ требует новый метод сервиса,
  он делается отдельным коммитом до экрана, а не внутри экрана;
- `doc/adr/0002-admin-panel-contract.md`.

**Гейты перед сдачей** (агент запускает один раз в конце, не в середине):

```bash
go build ./...
go vet ./...
go test ./admin/ ./internal/database/ -count=1
go test -race ./admin/ -count=1
golangci-lint run ./admin/... ./internal/database/...
cd admin && npm run build   # dist НЕ коммитить
```

**Сдача:** ветка `feat/admin-<entity>`, один коммит, сообщение
Conventional Commits без футеров. В описании — какие guard'ы покрыты тестами
и что осталось за скоупом.

## Готовые общие хелперы (использовать, не переписывать)

`admin/src/lib/api.js`:

```js
api.get(path)            api.post(path, body)
api.put(path, body)      api.del(path)
```

Ошибки приходят как `ApiError` с полями `status`, `code`, `message`,
`details` (если сервер их прислал).

`admin/src/lib/format.js`:

| Функция | Назначение |
|---|---|
| `formatMoney(cents, currency)` | центы → «399 ₽» |
| `formatDays(days)` | 30 → «30 дней» (плюрализация) |
| `formatDate(value)` | RFC3339 → «05.11.2026, 12:30» (локаль) |
| `formatGib(bytes)` / `bytesToGib` / `gibToBytes` | трафик |
| `humanError(err)` | код → русский текст, фолбэк на `message` |
| `errorMessages` | словарь кодов (расширяется интегратором) |

Специфичные словари (статусы заказов, названия событий аудита) держатся
локально во вью: это часть экрана, а не сквозное форматирование.

**Навигация.** Роутер — хеш в `App.svelte`, вложенный id поддержан:
`location.hash = '#/subscriptions/' + id`; detail-вью объявляет
`let { id } = $props()` и получает id строкой. Список id игнорирует.

## Общие технические требования

- Никаких новых npm-зависимостей и Go-модулей.
- Список: `{"items":[…],"total":N}`. Пагинация только там, где указано в ТЗ.
- `PUT` — полная замена редактируемых полей, лишние ключи → `400`.
- Мутация возвращает изменённый объект, `204` не используется.
- Секреты не попадают в JSON; вместо них `has_<secret>`.
- Единицы: байты / центы / дни; время RFC3339 UTC. Форматирование — только в
  `format.js`.
- Русские тексты в UI, английские идентификаторы и комментарии в коде.
- Sentinel-ошибки на каждый отказ, маппинг — через `writeStoreError`.
- DTO в `admin/`, модели БД в JSON не отдаются.
- Каждая мутация пишет аудит: `actor_type=admin`, `actor_id=0`,
  `service.WithAuditAdmin(ctx, 0)` для сервисных вызовов.
- Тесты — на реальной SQLite через `testutil`, без фейков БД.

## Деление работы

Экраны 01–03, 05, 07 независимы: их можно делать параллельно разными агентами
одновременно. Экран 04 требует готовых `RevokeSubscription` и
`ResetSubscriptionTraffic`, экран 06 — методов репозитория рассылок; эти
методы делаются отдельными коммитами и блокируют соответствующие экраны.

Порядок слияния: сначала экраны без зависимостей, затем сервисные методы,
затем 04 и 06. Интегратор после слияния: `cd admin && npm run build`, проверка
меню и маршрутов, коммит `dist`.
